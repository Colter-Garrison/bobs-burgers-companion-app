# Bob's Burgers Companion App

## Overview

A React Native app built with Expo, styled with NativeWind (Tailwind for RN), using the Bob's Burgers API (https://www bobsburgersapi.com/). Deployed to web via Netlify. Target: **web only** — it isn't shipped as an iOS/Android app, so web-specific solutions are fine.

## Tech stack

- React Native + Expo SDK 56 (React 19, React Native 0.85, react-native-web 0.21, Expo Router 56). Node >= 22.13.
- TypeScript
- Styling: NativeWind (Tailwind for RN)
- No backend and no accounts. `server/` (Express + Postgres + JWT auth) was deleted in priority #16 — the app talks only to the public Bob's Burgers API, and favorites are stored client-side.
- Package manager: npm
- Linting/formatting: ESLint 9 flat config (`eslint.config.js`, built on `eslint-config-expo/flat`) + Prettier, bridged via `eslint-plugin-prettier` so formatting issues surface as lint errors. `eslint-plugin-react-native-a11y` only ships legacy presets, so its rules are registered by hand in that file. Run `npm run lint` before considering any change done; `npx eslint . --fix` applies safe fixes.

## Conventions

- Match existing file/folder structure under `app/` (Expo Router convention) — don't introduce a different routing or folder pattern without asking first.
- Use TypeScript strictly — no `any` unless there's no reasonable alternative, and explain why if you do.
- Prefer functional components and hooks; no class components.
- Keep components small and focused; extract shared logic into `hooks/`.
- After completing a task in "Current priorities (in order)" cross off the task we completed instead of deleting it and renumbering the tasks.
- You can spin up Playwright, the front-end and back-end server, or anything else you need to self-verify but make sure to stop the process when you're done.

## Working style

- I'm new to AI-assisted coding — explain non-obvious changes as you make them.

## Testing

- Frontend unit/component tests: Jest (`jest-expo` preset) + React Native Testing Library. Run `npm test` (watch mode) or `npm run test:ci` (single run). Hook tests live next to their source (`hooks/*.test.ts`); screen tests live next to their source (`app/*.test.tsx`).
- Frontend E2E: Playwright, targeting the real static `expo export` build served locally (mirrors what Netlify actually serves in production). Run `npm run test:e2e`. Specs live in `e2e/`.
- New features should come with tests; don't skip this.
- CI: GitHub Actions (`.github/workflows/ci.yml`) runs typecheck, lint, Jest, and Playwright on every push to `main`/`dev` and on every pull request.

## Do not

- Don't add new dependencies without flagging it and explaining why.
- Don't rewrite unrelated files while working on a feature.
